# BatteryLife → 商飞 C1/C2：95% 容量寿命实验自检报告

审计日期：2026-10-09（北京时间）  
审计对象：`paper95_20261008_loader_v2_retrain`，三个随机种子 2021、42、2024。  
目的：检查是否使用 BatteryLife 原方法及公开数据训练 95% 寿命模型，并在完全不参与训练的商飞 C1/C2 上测试；逐项说明实现、改动与局限。

## 1. 结论先行

这次实验可以准确称为：**使用 BatteryLife 当前公开代码的 CPTransformer、现有 MIX_large 划分及已下载预处理数据，重新生成 95% 寿命标签并训练，随后对商飞 C1/C2 做不微调的跨域测试。**

但不能称为“严格复现原论文，除了标签之外完全相同”，原因如下：

1. **数据版本未锁定到原论文时期的 v4。**现有下载文件缺少完整的版本、原 ZIP 校验与下载清单，不能证明逐文件与 v4 相同。本次可以检验本地与服务器数据是否一致，不能据此证明与作者原实验数据一致。
2. **95% 标签改变了有效样本构成。**13 个数据集目录都在，但 843 个候选电芯中仅 468 个有效，只有 8 个数据集贡献有效电芯；不能说实际用完整 13 个数据集训练。
3. **商飞标签是代理口径。**379/419 是日常放电容量 `÷0.94÷183` 的首次阈值圈数，不是完整 RPT 实测寿命。固定 0.94 是本任务确定的假设，而非论文规定或模型学出的校正。
4. **一枚源域测试电芯的寿命标签有质量保留意见。**`ISU-ILCC_G43C3.pkl` 在首次有效阈值前存在容量缺失区间；1348 是“现有有效记录中的首次越阈位置”，无法保证是真实首次越阈圈。
5. **跨域预测效果差。**三个模型均大幅低估 C1/C2 寿命，误差约 68%–79%。计算一致不等于标签物理真实性得到证明，更不等于模型已经适用于商飞。

此次只做读数、重新推理与报告，不重训、不改正式标签、不按商飞结果选模型、不重新启动已取消的 80% 复现实验。

## 4. 95% 标签的实际实现

实现：[prepare.py](../experiments/mixed95/prepare.py)。逐电芯决定记录于 `source_labels_audit_95.json`，实际加载用 JSON 在独立 `dataset/mixed95/input/Life labels` 下，不覆盖原 80% 实验。

对每个已预处理循环，取放电容量数组中有限值的最大值 `Qd`。一般计算：

```text
SOH = Qd / (额定容量 Ah × |SOC_high − SOC_low|)
95% 寿命 = 首次存在有限 SOH ≤0.95 的已预处理循环位置（从 1 开始）
```

细节如下：

- 保留原仓库中的额定容量约定：RWTH 固定 1.85 Ah，`SNL_18650_NCA_25C_20-80` 固定 3.2 Ah，其余读 `.pkl` 元数据。SOC 区间来自 `.pkl`；非法或零跨度按完整跨度 1 处理。因此不是所有源电芯都仅除以额定容量，不应忽略部分 SOC 区间。
- XJTU 优先取负电流放电段的容量；没有该段时回退到有限容量记录。非正容量、全无有限容量的循环按缺失处理，不把 0 Ah 当成真实 SOH=0。
- 不平滑、不要求连续多圈越阈、不在缺失区间插值。寿命 ≤100 圈的电芯不进入本实验，防止早期输入窗口已经跨越寿命终点。
- 没有有效越阈时，末次 SOH 必须在 `(95%,97.5%]`，才取最后 20 个有效循环拟合“圈号对 SOH”的线性关系，预测 95% 处圈号并截断为整数。要求外推寿命晚于记录末圈且 >100，否则不生成标签。本次实际 **没有任何外推标签**。
- 末次 SOH>97.5%、末次无效、有效尾段不足、外推失败等均不生成有效真值。
- 源域标签的圈号是 `.pkl` 的循环列表位置，不保证等于原实验设备的 `cycle_number`。这是沿用原标签提取的序号约定；不能把它与商飞的物理圈号无条件视为完全相同的计数单位。

这些规则并非对原标签脚本仅替换 `0.8→0.95`：原通用脚本先看末次 SOH 决定排除/外推，本任务先找有效的首次越阈；原通用外推取最后 20 个列表位置，本任务取最后 20 个有效点。当前上游 XJTU 专用脚本还采用“最后一次向下穿越、线性插值并向上取整”，本任务按用户确定的规则统一为“首次有效 SOH≤95% 的记录位置”，只保留其放电段容量读取规则。以上均属于**显式标签定义适配**，不能声称与所有原数据集的标签提取算法逐字节相同。实际计算定义已写明且独立重算通过，但这不消除与原标签处理规则的差异。

原论文对未完全越阈的数据允许近阈值外推；本任务将阈值区间整体移至 95%–97.5%。[论文 §4.1](https://arxiv.org/html/2502.18807#S4.SS1)

### 4.1 标签质量保留意见

独立重算能确认“代码按照上述规则计算正确”，不能自动确认原始传感器容量记录都正确。468 个有效电芯中有 **29 个**包含非正/缺失容量（训练 13、验证 6、测试 10）；其中 28 个的这些位置在已经确定的 95% 标签之后，对首次越阈没有直接影响。

重点电芯 **`ISU-ILCC_G43C3.pkl`，源域测试集**：第 993–1127 个已预处理循环位置共 135 个缺失/无效容量；有效记录计算出的 95% 寿命为第 1348 个位置。缺失区间在标签之前，因此可能漏掉更早越阈。正式测试仍保留该电芯，不能对含它的 96 电芯指标作“标签完全无异常”的表述。这里说的是源域 ISU 数据，不是商飞 C1/C2。

审计 JSON 中 `bad_physical_positions` 是诊断字段名，实际含义为**预处理列表位置**，不是已经独立映射验证的原始物理圈号。

另有一个有效训练电芯 `HUST_7-5.pkl` 的原 `cycle_number` 从 3 开始；其列表位置 1442 对应原编号 1444。本实验标签与原加载器都使用重编号后的列表位置，内部一致，但这说明源域“圈号”并非所有电芯都保留原设备编号。

## 5. 模型、特征及训练实现

### 5.1 没有替换为另一个算法

入口：[train.py](../experiments/mixed95/train.py) 调用原 `run_main.py`，模型仍为原 [CPTransformer.py](../models/CPTransformer.py)。每圈 V/I/Q 三通道，充电、放电各重采样 150 点，合计 300；100 圈输入形状为 `100×3×300`。

每圈展开 900 维，经线性层到 256 维；1 层圈内 MLP、位置编码、12 层圈间 Transformer、展开后线性输出一个寿命值。可训练参数 **3,857,217**。不是逐圈 SOH 输出，也不是包含 80%、93%、95% 多个端点的联合模型；此次只训练 **95% 总寿命圈数**。配置中保留历史 `task_name=classification` 字样，但实际输出 1 个实数、损失为 MSE，是寿命回归。

原加载器按充/放电段、去静置阈值、线性插值与其既有端点规则提取特征，未改为新特征算法。归一化为：电压除以该圈重采样曲线最大电压，电流除以额定 Ah 得 C-rate，容量除以额定 Ah。这里没有用目标域拟合总体特征均值/方差；只有寿命标签 scaler 是训练集拟合统计量。

### 5.3 checkpoint 选择与测试集使用

训练 MSE，但 **checkpoint 和早停按照源域验证 MAPE**，不是验证 MSE，也不是源域测试指标，更不是商飞指标。原入口每个 epoch 都会计算源域验证集和测试集；保存的“最佳模型测试指标”对应验证 MAPE 最优的 checkpoint。没有对测试集反向传播，但也不能宣称源域测试只在训练结束后计算了一次。

## 6. 商飞适配：标签和模型输入是两条不同流程

### 6.1 全局圈号、去重和 RPT

读取 C1/C2 分段 Excel，不更改原文件。对标记 100/200/300/400/500 的区段：

```text
全局物理圈号 = 区段终点 − 100 + 表内局部圈号
例：C1-400-1.xlsx 的局部 79 → 全局 379
    C2-500.xlsx 的局部 19 → 全局 419
```

`-2` 文件是导出续段，不再加一个 100 圈区段。循环汇总只使用主文件，早期详细曲线合并 `-1/-2`、按完整记录去重并按时间稳定排序。

通过工步汇总识别 RPT；本数据对应全局圈 1、101、201、301、401。普通日常容量取 `循环数据表` 的 `放电容量(Ah)`，排除这些 RPT 汇总圈；完整 RPT 容量取其完整放电工步，单独保留。每枚电芯 495 个日常循环、5 个 RPT 点。两枚电芯 `capacity_issues.json` 都为空，没有因容量清洗改变 379/419。

### 6.2 95% 代理寿命复核

```text
SOH_proxy = 日常放电容量 / 0.94 / 183 Ah
95% 对应日常容量 = 0.95 ×0.94 ×183 = 163.419 Ah
```

| 电芯 | 阈值前一圈 | 容量 Ah | 首次 ≤95% 圈 | 容量 Ah | 结论 |
|---|---:|---:|---:|---:|---|
| C1 | 378 | 163.429 | 379 | 163.405 | 379 复现 |
| C2 | 418 | 163.424 | 419 | 163.399 | 419 复现 |

独立用 openpyxl 读取原 Excel，而不是调用生产标签函数，逐行核对共 990 个日常容量和 10 个 RPT 容量，与 v2 导出一致；同时重新计算阈值、圈号及首次越阈。

这证明代理标签的**计算和映射正确**。它不证明每天真实完整容量恰好等于日常容量÷0.94：仍需相同 SOC 覆盖、工况稳定和计量可靠等假设，无法仅凭现有稀疏 RPT 证明每一圈。

### 6.3 完整 RPT 对照

| 物理圈 | C1 完整 RPT SOH | C2 完整 RPT SOH |
|---:|---:|---:|
| 1 | 100.5219% | 100.7153% |
| 101 | 98.1842% | 98.4596% |
| 201 | 97.0082% | 97.3470% |
| 301 | 96.0087% | 96.3601% |
| 401 | 94.9328% | 95.3251% |

RPT SOH 是完整 RPT 放电容量÷183，不用 0.94。C1 首次**观测到**完整 RPT ≤95% 在 401 圈；不能据此断言实际首次越阈恰为 401，相邻采样跨越发生在 301–401 圈之间。若不额外假设单调衰减，稀疏点也不能排除更早的短暂越阈后恢复。C2 现有 5 个完整 RPT 点均未达到 95%。因此不能把 379/419 改写成“完整 RPT 测得寿命”。

邻近日常代理与 RPT 的差约 −0.241 至 +0.188 个百分点，说明两种曲线在这些稀疏位置较接近，但不是同圈逐点校准，也不足以证明固定 0.94 全寿命无偏。

对应图：[C1 代理与 RPT](../dataset/mixed95/comac_loader_v2/C1_proxy_vs_rpt.png)、[C2 代理与 RPT](../dataset/mixed95/comac_loader_v2/C2_proxy_vs_rpt.png)。

### 6.4 早期输入：只取物理第 1–100 圈

实现：[comac_input.py](../experiments/mixed95/comac_input.py)。输入 `float32`、形状 `100×3×300`，物理圈号恰为 1–100。RPT 第 1 圈为全零，mask=0；第 2–100 圈保持原位置，mask=1。没有补入第 101 圈及以后来凑满 100 个普通循环。

从早期详细表保留静置、电压、电流、累计充/放电容量。累计 Ah 先减去对应充/放电起点，转换为每圈每段 Ah，再**直接调用未改的 `Dataset_original.get_charge_discharge_curves`**，由原加载器决定分段和插值。

商飞输入特征：电流÷183、容量÷183、电压÷该圈重采样最大电压。**0.94 只作用于商飞寿命标签，不作用于模型容量特征。**标签生成可读后续循环以确定真值，但输入生成不能读入后续循环特征；这两者不可混淆为信息泄漏。

模型沿用原 attention mask 机制遮蔽缺失圈作为注意力键；没有新增插值圈、缺口预测器或改变输出结构。原模型最后仍展开所有 token 输出，缺失圈的查询输出不是被彻底删除。因此“保留掩码”不等于新设计的缺失数据鲁棒模型，首圈 RPT 缺口也有别于多数源域连续早期前缀。

### 6.5 曾经修正的分段边界问题

旧适配器单独按电流正负挑充放电点，与原加载器的端点规则不一致。v2 不再自定义分段，而是调用原加载器。尤其原充电优先路径将最后一个充电点排除出充电段、保留在放电段起点；这只是复用既有代码规则，不是提出新物理定义。

本次独立重构了 C1/C2 全部 **198 个早期普通循环**的数值处理，与 v2 输入在 float32 下完全相等。该数值交叉验证沿用同一个底层 Excel 行读取器；原汇总容量与 RPT 的核验则使用独立 openpyxl，因此不是声称所有步骤都由两个完全独立软件栈验证。

旧输入与旧结果仍保留。修正后按用户要求重新训练，但源域输入、标签和算法未变；新旧每个种子的权重哈希一致。该修正只改变目标输入的一致性，不构成依据商飞误差重新优化模型。历史上已经看过旧版商飞结果，所以 v2 更正和此次复算不能再被描述为全新盲测。

## 9. 交叉检验设计、通过条件与局限

没有仅把同一份结果 JSON 再读一遍就认定准确。此次核验分层如下：

1. **代码层**：本地上游快照差分、实际参数 JSON、远端代码 SHA；识别加载器分支修复和商飞适配，检查未改模型。
2. **数据层**：候选 843 文件逐个计算 SHA-256，对照本地与服务器；检查实际输入软链接指向指定下载数据。
3. **标签层**：本地与远端均用独立计算重新读取 `.pkl`；不调用生产 `life_from_soh`，比对状态、寿命和实际加载 JSON。诊断程序另写协方差形式的外推计算，但本数据没有外推样本，该分支在全数据复算中未被执行；外推边界由单元测试核验。
4. **Excel 层**：openpyxl 原表逐行核对 990 日常容量、10 RPT 点；独立阈值与映射核对，避免生产解析函数自身重复错误。
5. **特征层**：独立实现原端点与插值规则，重建全部 198 个早期普通循环，与 v2 数组严格比较；验证物理圈号、掩码和零填充，无第 101 圈及以后。
6. **权重层**：直接加载保存 safetensors 与 scaler，重跑源域验证/测试和 C1/C2；用独立 NumPy 指标公式计算，不调用正式商飞 evaluator，不从旧指标反推。
7. **文件保护层**：审计开始/结束计算正式 run 全部文件 SHA，验证正式结果及权重未被审计改写。
8. **边界单元测试**：`experiments.mixed95.test_mixed95` 与 `experiments.comac95.test_data` 合计 **23 项通过**，覆盖阈值、外推、排除、映射、续段、RPT、掩码、原分段一致性等。缓存与字体警告不属于测试失败。

数值容差事前设定：源域 MAE/RMSE 与日志差≤0.002 圈；MAPE 小数与日志差≤0.000051（容纳四位小数打印）；准确率与日志差≤0.000051 个百分点；验证 MAPE 与最优日志差≤0.000005；GPU 审计与 CPU 商飞正式预测差≤0.005 圈。容差用于打印舍入和设备浮点差异，不允许据误差大小调整。
